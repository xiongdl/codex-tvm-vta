# Intent: TSIM Benchmark Validation

- **Outcome:** Make all six MLPerf Tiny benchmarks pass TSIM deployment, fix the separate `test_benchmark_gemm` TVM storage bound failure, and identify and fix the native crash when the image classification V2 TSIM matrix calls `graph_executor.run()` inside the pytest process.
- **User:** Developers validating VTA TSIM benchmark deployments.
- **Why now:** The checkpoint3 run showed three benchmark preflight assertions rejecting the actual model structure, while the GEMM benchmark independently hits a TVM storage bound error. Follow-up testing found that running the V2 matrix from pytest could abort inside graph execution even though the production CLI passed; a subprocess test workaround hid that failure without identifying its native cause.
- **Success:** VWW and image classification v2 validate their observed 13 and 8 partition symbols; anomaly detection validates its actual convolution structure; all six TSIM benchmark deployment runs pass; `test_benchmark_gemm` passes its storage bound check; and the V2 TSIM matrix runs directly inside pytest without native abort after the underlying root cause is fixed.
- **Scope:** Inspect and adjust benchmark partition/model structural checks only where they conflict with the model artifacts; diagnose and fix the VWW TSIM runtime segmentation fault surfaced after its routing validation is corrected; diagnose and fix the GEMM storage bound issue at its source; investigate and fix the V2 in-process TSIM graph-execution crash at its actual cause, including a narrowly scoped shared TVM/VTA executor/runtime change and regression test when evidence requires it; run the narrowest validations that establish these criteria.
- **Always:** Preserve checks that validate real deployment assumptions and keep the distinction between benchmark preflight and TSIM deployment explicit in results.
- **Ask first:** Model/quantization changes, shared TVM/VTA changes outside the V2 in-process TSIM graph-execution crash boundary, other benchmark runtime changes beyond the listed structural validations, or changes to benchmark scope and success criteria.
- **Never:** Claim a benchmark passed TSIM deployment if it did not reach and complete the TSIM deployment step.
