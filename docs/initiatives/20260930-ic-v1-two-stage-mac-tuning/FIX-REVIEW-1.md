# Review round 1 fix: IC V1 deployment measurement equivalence

## Finding and root cause

The previously selected minimum native TSIM schedules for occurrences 2 and 5
exceeded the approved 10% deployment comparison: 11,507 vs 12,961 cycles
(12.6358%) and 7,097 vs 7,833 cycles (10.3706%). The deployment lowering in
`vta/python/vta/relay/transform.py::_pack_output_constant` expanded a rank-0
scalar bias into a packed accumulator tensor. This introduced two extra
`VTALoadBuffer2D` operations in the real deployed graph, while the AutoTVM
task represented the same scalar addition as a VTA ALU immediate.

Preserving scalar constants as rank-0 Relay constants aligns the deployment
lowering with the tuning computation and removes the unnecessary bias DMA.
The model's arithmetic, tensor geometry, useful-MAC denominator and selected
candidate rule are unchanged. No slower fallback, cycle rescaling, or relaxed
threshold is used. A focused IC V1 regression checks the actual legalized
graph; the BYOC lowering matrix verifies scalar and vector-bias cases in both
supported data/kernel layouts and evaluates numerical equivalence.

## Search provenance and selected minimum candidates

The fix changes only Relay lowering and regression tests. The AutoTVM workload
arguments, task implementation, FSIM/TSIM single-call measurement protocol,
geometry, model bytes and workload hashes remain unchanged, so the existing
complete search records are valid. The final manifest was regenerated by the
normal exporter from the C4 run state; all FSIM successes were already
measured on TSIM, and the unchanged exporter applied the existing
minimum-positive-native-cycle/deployable-candidate rule.

The all-workload search contains 1,691 failed FSIM trials and 209 distinct
successful schedules, all 209 with a completed TSIM result. No configuration
space was exhausted; each workload reached its 20-success quota. Selected
records, their hashes and the best manifest are in
`vta/apps/mlperf_tiny_benchmark/image_classification_v1/tune/optimal/c4-full/`.

The actual full-model deployment was remeasured with the updated lowering. All
ten committed samples match the pure HOST output. Debug and ordinary profiling
produce equal cycles. Baseline is 36,328,640 cycles for ten measured
invocations; tuned is 2,591,430. The ten-invocation logical MAC count is
120,586,240 in both cases. The model-independent calculator reports 5.1864%
baseline and 72.7073% tuned whole-model utilization (14.0188x fewer tuned
cycles). Per-occurrence utilization and exact report evidence are in
`tune/deployment-c4-full.json` and `tune/mac-utilization-c4-full.json`;
human-readable results are in `tune/REPORT-C4-FULL.md`.
