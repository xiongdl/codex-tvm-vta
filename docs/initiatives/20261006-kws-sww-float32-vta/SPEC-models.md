# Float Model Deployment and Gate
## Objective and Structure
KWS and SWW own independent float32 import, audio preprocessing, TVM quantization, routing and deployment under their existing application directories. Use specified models, copy KWS float model with provenance to local model directory. Validate actual shapes/dtypes/operator topology from FlatBuffers rather than keeping int8 metadata. Preserve MFCC/log-mel preprocessing, feeding float features without old int8 scale/zero point conversion.
## Preparation Contract
Follow image_classification_v1: import float32 TFLite; Relay quantize qconfig calibrate_mode=global_scale, global_scale=8.0, skip_conv_layers=[0]; bind params; partition_for_vta. CPU reference for mixed verification is the same quantized graph. Float source outputs and quantized outputs are distinct references; never claim bit exact equality across quantization. Unsupported operations remain CPU. No probes, no rewrite of pretrained weights, no compiler expansion.
Adapt model metadata, validators, reports and deployment tensor handling coherently; retain independent app ownership and no cross-app runtime import. CPU paths do not require simulator. Genuine VTA regions must contain source-model convolution and be compiled/executed, not just structurally counted.
## Workload Gate
For both models record hashes, operator topology, quantization policy, VTA symbols, CPU placement, model outputs, CPU/mixed equivalence and actual deployment measurements. Build and run selected deployment with first committed WAV and export real occurrence workloads/activations using vta_64mac.json, FSIM first. If either has zero regions, preserve a working CPU fallback with truthful zero coverage and no tuning evidence; stop whole task and report both available findings. Infrastructure failures are errors, not zero coverage. If nonzero regions fail lowering/execution, report concrete blocker; do not fabricate positive evidence.
## Commands and Verification
Use `.envs/tvm-vta-env/bin/python`, PYTHONPATH containing tvm/python and vta/python; VTA_CONFIG_FILE absolute vta/config/vta_64mac.json, VTA_BACKEND=fsim|tsim matched to SIMULATOR. App `make deploy TARGET=llvm`, then `TARGET=vta,llvm SIMULATOR=fsim EXPORT_WORKLOADS=...`; existing deploy CLI and Make contracts remain. Update stale int8 tests to actual float contracts, no blanket skips/deletion. Test malformed models, preprocessing contract, CPU isolation and real deployment/output verification. Record exact runnable commands in each README and evidence in initiative RESULTS.md.
## Boundaries and Style
No retraining, TensorFlow app runtime dependency or modifications to TVM/VTA compiler. Keep model ownership local. Preserve schedule/workload validation of model hash, config, activations and serialized graph. Dataclasses and explicit validation follow reference app.
