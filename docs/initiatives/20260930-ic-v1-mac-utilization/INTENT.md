# IC V1 MAC 利用率与 tuning 计算一致性

## Confirmed intent

2026-09-30 用户确认分析 IC V1 当前约 44.62% MAC 利用率，与同 workload、调度和周期统计口径下的 61.62% 对照；优先软件，再考虑硬件。原分析已提交并审核通过。

用户随后明确调整方向：不考虑权重及输入 tile 复用；解释 dump 中 NOP 多的原因；检查 tuning 是否缺少 ALU，并要求 tuning 算子与真实模型推理算子的计算一致，参考 `tvm/vta/scripts/`。

- 目标：解释 NOP 的生成机制和具体指令；修正 IC V1 tuning 所测计算，使其包含真实推理融合算子的计算语义，而非独立裸 Conv。
- 计算一致性：相同 GEMM、可选 bias、shift、clip、cast、dtype 与融合边界；具体属性来自真实模型，不能复制参考脚本的固定值。
- 测量一致性：FSIM 搜索与 TSIM 最终测量使用同一完整计算；MAC 分子仍只计卷积 MAC，周期包含融合后处理。
- 成功：真实融合算子与 tuning 候选输出一致，dump 显示适用 ALU，NOP 可按初始化/分块依赖/收尾同步解释；记录新 workload 身份和周期口径。
- 约束：软件优先；使用项目环境和既有模拟器；旧裸 Conv 数据保留，不能伪装成修复后的融合测量。
- 范围外：权重/输入 tile 复用、硬件改造、全量重新调优、恢复不可获取的历史改动、承诺达到 61.62%。

新方向由用户的明确指令授权；新的 SPEC 和 PLAN/TASKS 仍按 Root 规则分别进入审批门。
